# Feature docs

| Feature | What it does |
|---|---|
| [Agent modes](agent-modes.md) | The skill tells a coding agent how to write, bootstrap, trim, audit and publish one-page feature docs. |
| [Diagram checks](diagram-checks.md) | The doc linter parses every `mermaid` block and rejects diagrams that GitHub would fail to render or that explain nothing. |
| [Doc linter](doc-linter.md) | `lean-docs check` fails a markdown doc that is too long, hard to read, padded with filler, unportable, or names files that don't exist. |
| [Docs coverage](docs-coverage.md) | `lean-docs coverage` reports what share of the repo's source files some doc's Code table covers, and the folders with the most uncovered files. |
| [End-of-turn hook](stop-hook.md) | In Claude Code, the plugin runs a Stop hook that asks the agent once to update the docs its change made stale before it finishes. |
| [End-to-end evals](evals.md) | `evals/run.sh` hands small fixture repos to a real agent with the skill installed, then grades the doc it wrote. |
| [Feature index](feature-index.md) | `lean-docs index` prints one markdown table of every feature page in a folder, with each page's title and first sentence. |
| [GitHub Action](github-action.md) | The repo is also a composite GitHub Action that, on each PR, lists the pages the change updated and the docs it made stale, reports coverage, and lints feature docs. |
| [Stale docs](stale-docs.md) | `lean-docs affected` lists the docs whose covered code changed on this branch while the doc itself did not. |
| [Status command](status.md) | Running `lean-docs` with no arguments prints the state of a repo's docs in four lines. |
| [Wiki publishing](wiki-publish.md) | Publishing turns the feature pages into a wiki for people who don't read the code, such as product, support, ops and new joiners. |
