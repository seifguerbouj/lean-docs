# Write mode: "doc this feature"

Read `page.md` first for the shape and rules.

1. **Find what changed.** Run `git diff $(git merge-base HEAD main) --stat` plus `git status`, using the repo's default branch if it isn't `main`. If the user named files or a feature, start there.
2. **Find docs that already cover it.** Run `lean-docs affected`. If the change doesn't make a listed doc untrue (a rename, a refactor), tell the user; they can mark it with a `lean-docs-ok: <doc>` commit trailer. Every doc it lists describes code this change touched, so update those before writing anything new. A change that touches an existing feature usually needs an edit, not a new page.
   **Docs in the change are claims too.** If the diff adds or edits guides or a README, check what they say about the changed code against that code, as `audit.md` does. Put each contradiction in your report as `wrong`, with the file and line. Edit them only if the user asks.
3. **Read only what you need.** Read the changed files, then follow calls outward until you can draw the flow and name the failure modes. Don't explore the rest of the repo. In a big file, read the changed hunks and the functions around them, not the whole file.
4. **Find where docs go.** Look for an existing feature-docs folder (`docs/features/`, a Docusaurus `docs/`, `mkdocs.yml` `docs_dir`) and match its frontmatter and file extension (`.md` or `.mdx`). If a big multi-feature doc already covers this area, write the page in the features folder and add a one-line pointer to it in the big doc. Don't grow the big doc. In a monorepo where packages have their own docs folders, use the changed package's folder. With no convention, use `docs/features/<feature-name>.md`. If `mkdocs.yml` has a `nav:` (or Docusaurus a hand-written sidebar), add the page to it yourself and reread it: no other entry may move. If the site doesn't render mermaid (see `publish.md`), report the config to add.
5. **Write or edit the page.** When you edit an existing page, change only what the diff made untrue or incomplete, and keep the rest. List every file the page describes in `Code`.
6. **Reread it as the new teammate.** Can you answer the four questions from the page alone? If a word would stop you, add it to `Terms` or say it more plainly.
7. **Check it.** Run `lean-docs check --root . <page>`, then fix and rerun until it passes. If the folder has an index (a `README.md` whose first line says `generated by lean-docs index`), regenerate it with `lean-docs index <folder> > <folder>/README.md`.
8. **Report.** For a new page, show the cut list. For an edit to an existing page, use one line per page (see `page.md`).
